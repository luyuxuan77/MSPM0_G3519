# 编码器 + 陀螺仪航位推算实现流程

## 整体数据流

```
┌──────────┐    ┌──────────┐
│ 左轮编码器 │    │ 右轮编码器 │
│  (QEI)    │    │  (QEI)    │
└────┬─────┘    └────┬─────┘
     │               │
     ▼               ▼
┌──────────────────────────┐
│  motor_control_update()  │  每 128ms 运行
│  → 差分测速              │
│  → 低通滤波              │
│  → filtered_speed_M1/M2  │  ← 目前是 static，外部读不到
└──────────┬───────────────┘
           │
           ▼
    ┌──────────────┐     ┌──────────────┐
    │ 编码器计数/周期 │     │  陀螺仪 Yaw   │
    │  × 比例系数   │     │  (度)        │
    │  → 距离(cm)  │     │              │
    └──────┬───────┘     └──────┬───────┘
           │                    │
           └────────┬───────────┘
                    ▼
        ┌──────────────────────┐
        │   2D 航位推算         │
        │                      │
        │   dist = (L+R)/2     │
        │   x += dist·cos(yaw) │
        │   y += dist·sin(yaw) │
        └──────────┬───────────┘
                   ▼
            ┌──────────────┐
            │ LCD 显示坐标  │
            │ X: +025      │
            │ Y: -010      │
            └──────────────┘
```

---

## 需要改动的 6 个地方

### 第一处：电机模块暴露速度

**目标**：让外部模块能读到左右轮的滤波速度。

**现状**：`motor.c` 里 `filtered_speed_M1` 和 `filtered_speed_M2` 是 `static` 变量，外部访问不到。

**要做的**：
- `motor.h` 加一个函数声明 `void get_motor_speed(float *left, float *right);`
- `motor.c` 加一个函数实现，直接返回 `filtered_speed_M1` 和 `filtered_speed_M2`

---

### 第二处：INS 模块重写

**目标**：把原来"加速度积分→速度→位置"的旧逻辑，替换成"编码器距离+陀螺航向→位置"。

**现状**：`ins.c` 的 `INS_Update()` 接收 `ax, ay, yaw, dt`，对加速度做两次积分。这在消费级 IMU 上完全不可用。

**要做的**：
- 保留 `INS_Data_t` 或新建一个 `Odometry_t` 结构体，存 x, y, yaw, distance
- 新写一个更新函数，入参是：`左轮速度, 右轮速度, 陀螺 yaw 角度`
- 内部逻辑：
  1. 编码器计数 × 比例系数 → 厘米距离
  2. `dist = (左轮距离 + 右轮距离) / 2`
  3. `x += dist × cos(yaw_rad)`
  4. `y += dist × sin(yaw_rad)`
- 加一个 `INS_Reset()` 把坐标清零

**关键参数**：`ENCODER_COUNTS_PER_CM`，编码器计数到厘米的转换系数。需要实测——让小车跑 50cm，看编码器走了多少计数，反算出来。

---

### 第三处：主循环调度

**目标**：把 IMU 数据读取和 INS 更新挂进主循环。

**现状**：`main.c` 里 IMU 读取被注释掉了，INS 更新也被注释掉了。

**要做的**：
- 解开 IMU 读取，比如每 20ms 调一次 `IMU_getData()`，更新全局的 `Yaw` 变量
- 在 `motor_control_update()` 之后（128ms），调 INS 更新函数，传入编码器速度和 Yaw
- 可选：每 500ms 打印一次坐标或更新 LCD

---

### 第四处：LCD 显示坐标

**目标**：在屏幕上看到实时坐标。

**现状**：LCD 上已经有灰度传感器值和 goffset 占了一些行。

**要做的**：
- 在 LCD 空白区域（比如 y=90 以下）显示 X, Y, Yaw, 累计里程
- 可以放在 `Track_Direction_Control()` 末尾，或者在 500ms 定时任务里更新

---

### 第五处：位置归零

**目标**：按键一键清零坐标。

**现状**：`KEY/key.c` 已经有 `key1_flag`（Key1 按下次数）。

**要做的**：
- 在主循环或 INS 更新逻辑里检测 `key1_flag`
- 如果为真 → `INS_Reset()` → 清零 → 用户看到 LCD 上坐标归零

---

### 第六处：校准

**目标**：确定编码器计数到实际距离的换算系数。

**要做的**：
- 在 `ins.h` 里放一个 `#define ENCODER_COUNTS_PER_CM 100`（先给个估计值）
- 实测：让小车直线跑 50cm，看 LCD 上显示的里程是多少
- 调整系数直到显示准确

---

## 总结

| 步骤 | 文件 | 做什么 |
|---|---|---|
| ① | `motor.h` / `motor.c` | 暴露左右轮速度 |
| ② | `ins.h` / `ins.c` | 重写为编码器+陀螺 2D 推算 |
| ③ | `main.c` | 解开 IMU + INS 调度 |
| ④ | `control.c` | LCD 显示 X / Y / Yaw |
| ⑤ | `main.c` 或 `control.c` | 按键归零 |
| ⑥ | `ins.h` | 校准系数 `ENCODER_COUNTS_PER_CM` |
